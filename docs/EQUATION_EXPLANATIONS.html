Comprehensive Mathematical Formulations

Detailed Mathematical Mechanics of DINOv2 Vision Transformers, 6-Channel nnU-Net Segmentation, and CTC-HTR Optical Character Recognition

1. Self-Supervised Vision Transformer (DINOv2) Mechanics

DINO 1 Patch Embedding & 2D Position Encoding
$$\mathbf{x}_0 = \left[ \mathbf{x}_{\text{cls}}; \, \mathbf{x}_p^1 \mathbf{E}; \, \mathbf{x}_p^2 \mathbf{E}; \, \dots; \, \mathbf{x}_p^N \mathbf{E} \right] + \mathbf{E}_{\text{pos}}, \quad \mathbf{E} \in \mathbb{R}^{(P^2 C) \times D}, \quad \mathbf{E}_{\text{pos}} \in \mathbb{R}^{(N+1) \times D}$$
Mathematical Variables:
  • \(P = 14\): Patch dimension (\(14\times 14\) pixels); \(C = 3\): RGB channels; \(P^2 C = 588\) input features per patch.
  • \(\mathbf{E}\): Linear projection matrix mapping raw image pixels into \(D = 768\) latent embedding space.
  • \(\mathbf{x}_p^i\): The flattened \(i\)-th image patch on the manuscript folio.
  • \(\mathbf{E}_{\text{pos}}\): Learnable 2D positional encodings providing spatial coordinates of text lines on the page.
  • \(\mathbf{x}_{\text{cls}}\): Global classification token capturing overall folio illumination state.
How it works on Indic manuscripts: The manuscript image is diced into a grid of \(N\) spatial tokens. The linear projection preserves high-frequency stroke details while mapping them into a dense 768-dimensional space.
DINO 2 Multi-Head Self-Attention (MHSA) Spatial Manifold Extraction
$$\mathbf{Q} = \mathbf{X} \mathbf{W}_Q, \quad \mathbf{K} = \mathbf{X} \mathbf{W}_K, \quad \mathbf{V} = \mathbf{X} \mathbf{W}_V$$ $$\text{Attention}(\mathbf{Q}, \mathbf{K}, \mathbf{V}) = \text{softmax}\left( \frac{\mathbf{Q} \mathbf{K}^T}{\sqrt{d_k}} \right) \mathbf{V}$$ $$\text{MultiHead}(\mathbf{X}) = \left[ \text{head}_1; \, \text{head}_2; \, \dots; \, \text{head}_h \right] \mathbf{W}_O, \quad h = 12, \, d_k = 64$$
Mathematical Variables:
  • \(\mathbf{Q}, \mathbf{K}, \mathbf{V}\): Query, Key, and Value matrices projected via weight matrices \(\mathbf{W}_Q, \mathbf{W}_K, \mathbf{W}_V \in \mathbb{R}^{D \times d_k}\).
  • \(\frac{\mathbf{Q} \mathbf{K}^T}{\sqrt{d_k}}\): Scaled dot-product pairwise affinity matrix measuring structural correlation between distant patches.
  • \(\text{softmax}(\dots)\): Normalizes attention weights across the entire page (summing to 1 across rows).
  • \(h = 12\): 12 distinct attention heads tracking character lines, margins, headlines, and damage independently.
How it works on Indic manuscripts: Queries and Keys allow patches containing text ink to attend strongly to adjacent characters along the same line while ignoring unwritten margins, creating distinct text manifolds without any supervised training.
DINO 3 Spatial Feature Grid & Cosine Similarity Affinity
$$\mathbf{F} = \text{Reshape}\left( \mathbf{Z}_{1:N}, \left(\frac{H'}{14}, \frac{W'}{14}, 768\right) \right)$$ $$A_{ij} = \frac{\mathbf{z}_i \cdot \mathbf{z}_j}{\|\mathbf{z}_i\|_2 \|\mathbf{z}_j\|_2} = \cos(\theta_{ij})$$
Mathematical Variables:
  • \(\mathbf{Z} \in \mathbb{R}^{N \times 768}\): Token representations extracted from the final Transformer block.
  • \(\mathbf{F}\): 3D spatial feature tensor matching the 2D layout coordinates of the physical folio.
  • \(A_{ij}\): Cosine similarity between feature vector \(\mathbf{z}_i\) of patch \(i\) and \(\mathbf{z}_j\) of patch \(j\).
How it works on Indic manuscripts: Patches containing Sanskrit letters have a cosine similarity \(A_{ij} > 0.85\) to one another, while blank substrate patches cluster at \(A_{ij} < 0.20\), enabling zero-shot layout discovery.

2. 6-Channel nnU-Net Deep Semantic Segmentation Engine

nnU-Net 1 Encoder-Decoder Feature Propagation & Instance Normalization
$$\mathbf{x}^{(l)} = \text{LeakyReLU}_{\alpha=0.01}\left( \text{IN}\left( \mathbf{W}_2^{(l)} * \text{LeakyReLU}\left( \text{IN}\left( \mathbf{W}_1^{(l)} * \mathbf{x}^{(l-1)} \right) \right) \right) \right)$$ $$\text{IN}(\mathbf{v}) = \gamma \left( \frac{\mathbf{v} - \mu(\mathbf{v})}{\sqrt{\sigma^2(\mathbf{v}) + \epsilon}} \right) + \beta, \quad \mu(\mathbf{v}) = \frac{1}{HW}\sum_{y=1}^H \sum_{x=1}^W v(x,y)$$
Mathematical Variables:
  • \(\mathbf{x}^{(l)}\): Feature activation tensor at depth level \(l \in \{1, 2, 3, 4, 5\}\).
  • \(\mathbf{W}_1, \mathbf{W}_2\): Convolutional kernels (\(3\times 3\) receptive fields).
  • \(\text{IN}(\mathbf{v})\): Instance Normalization computed across the spatial dimensions \((H, W)\) of each individual folio.
  • \(\gamma, \beta\): Learnable affine scale and shift parameters; \(\epsilon = 10^{-5}\): Stability constant.
Why Instance Normalization: Batch Normalization fails when batch size is small or manuscript dimensions vary wildly. Instance Normalization normalizes each folio independently, preventing contrast distortion.
nnU-Net 2 6-Channel Softmax Probability Distribution
$$P(C = c \mid x, y) = \frac{\exp\left( z_c(x, y) \right)}{\sum_{k=1}^{6} \exp\left( z_k(x, y) \right)}, \quad c \in \{1, 2, 3, 4, 5, 6\}$$ $$\hat{Y}(x, y) = \arg\max_{c \in \{1, \dots, 6\}} P(C = c \mid x, y)$$
Target Class Definitions:
  • \(c=1\): TextRegion (Main body of Sanskrit verses)
  • \(c=2\): Marginalia (Margin glosses, header titles, folio numbers)
  • \(c=3\): GraphicRegion (Woodblock illustrations, deity paintings, decorative borders)
  • \(c=4\): PageFrame (Outer physical substrate boundary)
  • \(c=5\): Damage (Punched string binder holes, insect boreholes, physical tears)
  • \(c=6\): TextLine (Individual line baselines and polygons)
nnU-Net 3 Multi-Scale Deep Supervision Compound Loss
$$\mathcal{L}_{\text{total}} = \sum_{s=0}^{2} w_s \left[ \lambda_1 \mathcal{L}_{\text{Focal}}(\hat{\mathbf{Y}}_s, \mathbf{Y}_s) + \lambda_2 \mathcal{L}_{\text{Dice}}(\hat{\mathbf{Y}}_s, \mathbf{Y}_s) \right]$$ $$\mathcal{L}_{\text{Focal}} = -\frac{1}{N} \sum_{i=1}^N \alpha_t (1 - p_{t,i})^\gamma \log(p_{t,i}), \quad \gamma = 2.0, \, \alpha_t = 0.25$$ $$\mathcal{L}_{\text{Dice}} = 1 - \frac{2 \sum_{i=1}^N p_{t,i} y_{t,i} + \epsilon}{\sum_{i=1}^N p_{t,i}^2 + \sum_{i=1}^N y_{t,i}^2 + \epsilon}$$
Mathematical Variables:
  • \(s \in \{0, 1, 2\}\): 3 decoder resolution scales: \(512\times 512\) (\(w_0=1.0\)), \(256\times 256\) (\(w_1=0.5\)), and \(128\times 128\) (\(w_2=0.25\)).
  • \(\mathcal{L}_{\text{Focal}}\): Focal Loss with focusing parameter \(\gamma=2.0\) downweighting easy background pixels to focus on hard, degraded characters.
  • \(\mathcal{L}_{\text{Dice}}\): Squared Soft Dice Loss directly maximizing polygon boundary Intersection over Union (IoU).
Why this combination: Text lines occupy only ~8% of the image. Standard Cross-Entropy biases heavily toward the empty background; Compound Focal-Dice loss eliminates this class imbalance completely.

3. Optical Character Recognition (OCR & HTR) Mathematical Engine

OCR 1 Recurrent Feature Sequence Formulation (CRNN)
$$\mathbf{x}_t = \text{CNN}(\text{Line\_Crop}_{[:, \, t]}), \quad t \in \{1, 2, \dots, T\}$$ $$\mathbf{h}_t = \left[ \overrightarrow{\text{LSTM}}(\mathbf{x}_t, \overrightarrow{\mathbf{h}}_{t-1}); \, \overleftarrow{\text{LSTM}}(\mathbf{x}_t, \overleftarrow{\mathbf{h}}_{t+1}) \right] \in \mathbb{R}^{2 D_{\text{hidden}}}$$ $$\mathbf{y}_t = \text{softmax}\left( \mathbf{W}_{\text{out}} \mathbf{h}_t + \mathbf{b}_{\text{out}} \right) \in \mathbb{R}^{|\Sigma| + 1}$$
Mathematical Variables:
  • \(T\): Number of horizontal time steps across the segmented text line crop.
  • \(\mathbf{h}_t\): Bidirectional LSTM state combining past (left-to-right) and future (right-to-left) context of adjacent Devanagari Aksharas.
  • \(\Sigma\): Devanagari Unicode character vocabulary ($|\Sigma| = 128$ consonants, matras, viramas, numerals) plus 1 blank token \(\epsilon\).
  • \(\mathbf{y}_t\): Probability distribution over all possible characters at time step \(t\).
How it works on Indic text: Devanagari characters modify their appearance based on surrounding vowels (e.g., "क" vs "कि" vs "कु"). The bidirectional LSTM captures characters before and after the current position to correctly resolve ligatures and conjuncts.
OCR 2 Connectionist Temporal Classification (CTC) Conditional Probability
$$P(\boldsymbol{\pi} \mid \mathbf{X}) = \prod_{t=1}^T y_{\pi_t}^t, \quad \boldsymbol{\pi} = (\pi_1, \pi_2, \dots, \pi_T), \, \pi_t \in \Sigma \cup \{\epsilon\}$$ $$P(\mathbf{Y} \mid \mathbf{X}) = \sum_{\boldsymbol{\pi} \in \mathcal{B}^{-1}(\mathbf{Y})} P(\boldsymbol{\pi} \mid \mathbf{X})$$ $$\mathcal{L}_{\text{CTC}} = -\ln P(\mathbf{Y}^* \mid \mathbf{X}) = -\ln \sum_{\boldsymbol{\pi} \in \mathcal{B}^{-1}(\mathbf{Y}^*)} \prod_{t=1}^T y_{\pi_t}^t$$
Mathematical Variables:
  • \(\boldsymbol{\pi}\): A frame-level alignment path of length \(T\).
  • \(\mathcal{B}\): The CTC collapse operator that removes consecutive duplicate characters and deletes blank tokens \(\epsilon\):
    $$\mathcal{B}(\text{"क" } \epsilon \text{ "क" "क" } \epsilon \text{ "ष"}) = \text{"क" "क" "ष"}$$
  • \(\mathbf{Y}^*\): The ground-truth Sanskrit word/sentence string.
  • \(\mathcal{L}_{\text{CTC}}\): CTC Loss minimized during neural network training via Forward-Backward dynamic programming.
Why CTC is essential: In historical manuscripts, character widths vary widely (an Akshara with a matra is wider than a single consonant). CTC eliminates the need for manual character-by-character timestamp alignments.
OCR 3 Beam Search Decoding with Devanagari Language Model
$$\hat{\mathbf{Y}} = \arg\max_{\mathbf{Y}} \left( \log P_{\text{CTC}}(\mathbf{Y} \mid \mathbf{X}) + \alpha \log P_{\text{LM}}(\mathbf{Y}) + \beta \, |\mathbf{Y}| \right)$$ $$P_{\text{LM}}(\mathbf{Y}) = \prod_{i=1}^{M} P(w_i \mid w_{i-1}, w_{i-2}, \dots, w_{i-n+1})$$
Mathematical Variables:
  • \(\hat{\mathbf{Y}}\): Optimal decoded Sanskrit transcription string.
  • \(\alpha = 0.65\): Language model weight balancing acoustic visual predictions with Sanskrit phonetic grammar.
  • \(\beta = 1.20\): Word insertion bonus preventing the beam search decoder from favoring unnaturally short words.
  • \(P_{\text{LM}}(\mathbf{Y})\): $N$-gram Language Model probability over Sanskrit lexical corpus (validating legal Sanskrit root stems).
How it works in practice: If degraded ink makes it difficult to distinguish "ध" (Dha) from "घ" (Gha), the Language Model probability \(P_{\text{LM}}\) verifies Sanskrit vocabulary to select the phonetically correct word automatically.
