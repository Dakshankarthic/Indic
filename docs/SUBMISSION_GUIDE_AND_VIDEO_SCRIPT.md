## Method Summary

Our method is a geometry-first automated annotation pipeline for Indic manuscript and Ramcharitmanas pages.

The pipeline separates page understanding into three stages:

1. DINOv2 zero-shot layout analysis
2. Grayscale/binary image processing for text line, word, character, illustration, and damage structure
3. U-Net based semantic segmentation for page frame, text regions, marginalia, illustrations, and damage/hole detection

This is designed for the challenge's human-effort objective: missing text and badly shaped polygons are expensive for annotators to correct, so the system prioritizes complete geometry, simple polygons, and readable visual verification.

## Grayscale And Binary Processing

Each page is converted to grayscale and adaptively thresholded. This creates an ink mask where foreground strokes are separated from the page background.

The binary mask is used for:

- text-line splitting by horizontal projection,
- column separation by vertical projection,
- connected-component analysis for word and character/glyph boxes,
- illustration rejection so OCR is not run over figures,
- visual overlays for debugging and explanation.

## DINOv2 Layout Detection

DINOv2 is used as a frozen visual feature extractor. The page is divided into patch tokens, and K-Means clustering separates likely text/foreground regions from background.

The method adapts to two page types:

- Printed/light-background pages use a two-cluster foreground/background split.
- Manuscript/palm-leaf style pages use a three-cluster split where the border cluster is treated as background.

After clustering, OpenCV morphology smooths the mask and connects fragmented text patches into usable layout regions.

## U-Net Damage Hole And Extra Region Detection

The U-Net is trained on zero-shot masks generated by the DINO/OpenCV pipeline.

It predicts six channels:

1. text region
2. marginalia/notes
3. illustration/diagram
4. page frame
5. damage/hole
6. text line

The damage/hole channel is especially useful for palm-leaf manuscripts because binder holes, tears, stains, and missing areas should not be mistaken for text. After U-Net prediction, masks are converted into polygons using OpenCV contour extraction and polygon simplification. This gives cleaner PAGE-XML regions and reduces manual correction effort in Aletheia.

## OCR/Text Recognition

For the current test run, DINO/OpenCV detects line and region geometry, while Tesseract with Sanskrit trained data is used for word-level and character-level text extraction where applicable.

Illustration regions are masked before OCR so the recognizer does not hallucinate text inside drawings.

Character-level recognition is treated as a weak/debug signal, not the main claim. Devanagari characters are visually complex because vowel signs, halants, conjuncts, and the headline often overlap. For this reason, the final explanation should emphasize page layout, text-line detection, word regions, and line-level OCR rather than claiming highly accurate per-character boxes.

For demo visuals, keep red character boxes disabled. The clean visual should show green text lines, blue word-level regions, and cyan illustration regions. CER should be computed from predicted text strings against reference text, not from whether every visual red character box looks perfect.
